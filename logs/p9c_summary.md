# P9c screenshot security test fix — 食记

The change is limited to `ScreenshotSecurityTest.passwordDismissalAndNavigationRestoreScreenshotsInBothThemes` and this requested summary.

The root cause is conditional composition of the floating navigation capsule. `ScreenFrame` computes `ime = maxOf(reportedIme, legacyIme)` and invokes its floating `bottomBar` only when `floatingBottomBar && ime == 0` (`android/feature/src/main/kotlin/top/alanvampuke/dininglog/feature/components/QuietGridComponents.kt:78`). Password-dialog dismissal can finish disposing `SecureScreen`, clearing the activity's `FLAG_SECURE`, before platform IME insets settle. The settings composition survives, but a nonzero inset removes the entire capsule, including `tab:restaurants`, from both semantics trees.

`BottomTabs` puts each tag on the clickable `Surface` itself; the surface is a semantics merge boundary. Its enclosing `Row` and overlay `Box` do not merge or clear those tab semantics. Compose's test owner searches all registered roots, including dialogs, so the lookup is not restricted to the dismissed dialog window. Compose UI test 1.8.2 also checks the unmerged tree when a merged lookup fails and adds a hint if it finds a match there; the retained failure contains no such hint. Changing only `useUnmergedTree` cannot restore a tab that was not composed.

The exact fix is in `android/app/src/androidTest/kotlin/top/alanvampuke/dininglog/product/ScreenshotSecurityTest.kt:31`: place the real restaurant/settings screens in a weighted `Box` within a full-size `Column`, and compose the real `BottomTabs(tab) { tab = it }` as an unconditional sibling below that box. Pass an empty bottom bar to the screens. The test column applies navigation-bar and IME padding so the tabs remain available for touch navigation as insets change. Replace the keyboard-hide/wait workaround with `assertExists().assertIsDisplayed().performClick()` in `tapTab` at line 69. The click still executes the real tab's selection callback and must reach the restaurant screen before the final secure-flag assertion.

All five existing secure-flag assertion sites are unchanged: initial restaurant list CLEAR, ordinary settings CLEAR, password dialog SET, settings after dismissal CLEAR, and restaurant list after navigation CLEAR. The light/dark loop, two dialog dismissals per theme, screen-presence assertions, and UI-thread window-bit comparison are byte-for-byte unchanged.
