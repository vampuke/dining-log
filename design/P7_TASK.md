# P7 任务书：BITE! 潮流贴纸风视觉重构

## 0. 目标与边界

把现有 Android 应用的**视觉风格**从 D2 Quiet Grid（冷峻网格）重构为 **BITE! 潮流贴纸风（Neo-Brutalism 波普）**。

**设计稿（唯一视觉参考，必须在动手前完整读一遍）：**
`design/bite/BITE_DESIGN_REFERENCE.html`

这份 HTML 是可交互原型，用浏览器打开能看到：3 种视图模式（手机原型 / 4 屏总览 / 8 款图标库）、真实可点的表单、完整配色与组件规范。**它包含设计者手写的 SVG 图标路径，直接可用，不要自己另画一套。**

### 绝对边界（违反即失败）

1. **不改业务逻辑**。不动机器学习层、不改 API 调用、不改数据模型语义、不改 Room 缓存策略、不改草稿状态机、不改冲突处理、不改鉴权流程。
2. **不改后端**。本期不新增端点、不改 migration、不改 contracts。
3. **不改测试意图**。可以更新选择器和颜色断言以匹配新视觉，但不得降低断言标准（例如首屏 ≥3 条记录、对比度 ≥4.5 这类必须保留）。
4. **不引入位图资源**。所有图标、装饰、纹理必须是 vector XML 或 Compose Canvas 绘制。禁止 png/jpg/webp。
5. 全部 UI 文案保持中文（现有风格）。

## 1. 关键约束：设计稿有三个必须修正的地方

设计稿是视觉参考，不是可以照抄的实现。以下三点**必须**按本节处理，不能原样落地。

### 1.1 深色模式必须补齐（最重要）

设计稿是纯浅色方案（奶油底 `#FFFDF5`、波点背景、黑色描边），**没有任何深色变体**。

用户手机常开深色模式。如果直接照搬，深色下会出现奶油色背景配浅色文字的灾难。

**要求：**

- 保留 BITE! 的视觉语言（粗黑描边、硬投影、贴纸感、模压白边），但必须给出**完整的深色主题 token 表**
- 深色下不能用纯黑描边（`#111111` 在黑底上等于没有描边）——描边要换成亮色（例如 `#F5F2E8`）或高对比中性色
- 硬投影在深色下也要可见：不是黑投影压黑底，而是改用亮色投影或降低不透明度的反差色
- 奶油底 `#FFFDF5` 在深色下应映射为深暖灰（例如 `#14120E` 一带），保持"手账纸感"但不刺眼
- 波点/半调纹理在深色下要降对比，不能变成噪点
- 在 `P7_DONE.md` 给出**两张完整 token 对照表**（浅色 / 深色），每个 token 必须注明用途

### 1.2 两处对比度不达标（我已实测）

用 WCAG 公式实测设计稿配色：

```
白字 on 番茄红 #FF595E  → 3.07  FAIL（正文需 ≥4.5）
白字 on 克莱因蓝 #3A86FF → 3.48  FAIL
```

设计稿在 `.px-2.5 py-0.5 bg-popRed text-white`（"+ 记一笔"按钮、踩雷标签）和 `bg-klein text-white`（地址标签）里大量使用了这两种组合，都是**小字号正文**，属实质性可读性问题。

**已验证的修法**（改用近黑字，保留撞色冲击力）：

```
黑字 #111111 on 番茄红 #FF595E  → 6.15  PASS
黑字 #111111 on 克莱因蓝 #3A86FF → 5.43  PASS
```

其他组合实测均达标，可直接采用：ink on butter 13.38 / ink on mint 10.01 / ink on bubble 7.30 / ink on cream 18.54 / ink on peach 9.20。

**要求：** 落地方案必须让所有正文组合 ≥4.5:1，大字（≥18sp 或 ≥14sp 粗体）≥3.0:1。深浅两套主题都要满足。

### 1.3 设计稿的数据模型和本项目不一致

设计稿是独立原型，它展示的几样东西在当前 schema 里不存在，**不允许为此改数据库**：

| 设计稿展示 | 实际情况 | 处理方式 |
|---|---|---|
| 菜品四档结论「惊艳/推荐/一般/踩雷」 | `dishes` 表无此字段，只有 `rating_tenths` + `review` | 用**已有评分**推导档位：≥4.6 惊艳 / ≥4.0 推荐 / ≥3.2 一般 / <3.2 踩雷。未评分显示中性态 |
| 餐厅卡片上的「就餐日期」 | `restaurants` 表无日期字段，日期在 `visits` | 用 `RecordSummary.updatedAt` 或关联 visit 的最新 `dining_date`；两者都拿不到时**省略该行**，不要显示假日期 |
| 顶部统计「已打卡餐厅/平均美味度/已测评菜品」 | 无聚合端点，列表只有当前页数据 | 只用**当前已加载数据**计算，且标明是当前范围（例如「已加载 N 家」）。**不得伪造全量统计**，不得新增后端端点 |

**餐厅状态标签**（封神必吃 / 值得二刷 / 普通便餐 / 踩雷预警）可以直接用 `rating_tenths` 推导，这个没有问题。

## 2. 视觉落地规范

### 2.1 配色

从设计稿提取的主色板：

```
cream   #FFFDF5   手账暖米底
paper   #FAF4E4   次级纸面
ink     #111111   墨黑（描边/正文）
butter  #FFD60A   奶油芝士黄
popRed  #FF595E   番茄波普红
mint    #06D6A0   薄荷苏打绿
klein   #3A86FF   克莱因电光蓝
lilac   #8338EC   紫罗兰
peach   #FF9F1C   蜜桃橙
bubble  #FF70A6   泡泡糖粉
```

### 2.2 组件参数（设计稿已给出，直接采用）

- **描边**：主卡片 2.5–3dp 纯黑；内部胶囊 1.5dp
- **硬投影**：`blurRadius = 0dp`，X/Y 偏移 4dp；按压态偏移缩到 1dp 并下移
- **模切贴纸（Die-Cut）**：外层 3dp 纯白描边 + 内层 2.5dp 纯黑描边，配 −3° ~ +3° 微倾角
- **按压动效**：`translate(2px, 2px)` + 投影缩到 1px，120ms `cubic-bezier(0.2, 0.8, 0.2, 1)`
- **锯齿小票**：上下边缘用 `repeat-x` 三角锯齿（16px 周期，8px 齿深）
- **半调网点**：`radial-gradient(rgba(17,17,17,0.14) 1.5px, transparent 0)`，8px 间距

在 Compose 里：
- 硬投影用 `Modifier.shadow()` 会带模糊，**不行**。必须用 `drawBehind` 画偏移实心矩形，或用 `Modifier.offset` + 底层 Box
- 锯齿边缘用 `Canvas` + `Path` 绘制三角波
- 倾角用 `Modifier.rotate(angle)`
- 这些都应该抽成可复用的 Modifier 扩展，不要在每个屏幕里重复写

### 2.3 8 款应用图标

设计稿 `STICKER_ICONS` 数组里有 8 款手绘 SVG，含完整路径数据：
V1 波普笑脸汉堡 / V2 一番拉面热气 / V3 复古小票印章 / V4 BITE! 咬一口吐司 / V5 寻味坐标餐叉 / V6 必吃封神皇冠价签 / V7 米其林揭秘餐盖 / V8 吃货手账本叉勺

**要求：**

- 从 SVG 转换成 Android VectorDrawable（`res/drawable/*.xml`）
- 选一款作为最终应用图标（`ic_launcher` 系列），其余可作为可选主题留在代码里
- 自适应图标三层都要给（background / foreground / monochrome），Android 13+ 单色主题图标必须能看
- 现有的 `ic_launcher_foreground.xml` / `ic_launcher_background.xml` 会被替换
- 深色壁纸与浅色壁纸下都要能辨认（这是图标不是界面，不需要 4.5:1，但必须清晰）

### 2.4 底部导航图标

设计稿底部是"贴纸胶囊 + 中央大加号"的形态。落地方案：

- 三个 tab 用矢量图标（餐厅/到店/我的），保持选中/未选中的形状差异（描边 vs 实心），不靠颜色区分
- 中央大加号是「新增」快捷入口，需保留 `testTag` 并可被无障碍读取
- 现有 `testTag("tab:restaurants")` / `tab:visits` / `tab:settings` 必须保留，测试依赖它

## 4. 必须保留的功能行为

改造后以下行为必须仍然工作（现有测试会验证）：

- 深色模式自动跟随系统
- 页面切换动效 + 尊重「移除动画」设置
- 同 tab 重复点击不重建、滚回顶部
- 首屏 360×640 至少可见 3 条完整记录（浅色、深色各测）
- 空地址、空备注优雅降级，不渲染 `null` / `--`
- 应用内更新入口在「我的」页
- 所有现有 `testTag` 保持不变（`record:*`、`screen:*`、`tab:*`、`search`、`add`、`refresh`、`filters` 等）
- 无障碍：可读的 contentDescription，点击区域 ≥48dp
