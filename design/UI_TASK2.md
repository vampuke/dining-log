# 任务：打磨三套原型 + 补 DIRECTIONS.md（第二轮）

- `d1-ledger.html`（账簿 / Ledger）
- `d2-quiet-grid.html`（Quiet Grid）

三份都是单文件自包含、5 屏 × 393×852、带浅色/深色切换的 HTML 画廊。**方向本身保留，不要推倒重来。**
本轮只做两件事：**修掉下面这些已实测确认的缺陷**，然后**补上 `DIRECTIONS.md`**。

## 一、必须修的缺陷（三个文件都要改，逐条核对）

### A. 信息重复与语义
1. 顶部右上和列表区各出现一次「8 家餐厅」→ 只保留列表区那一处，顶部改成别的东西（例如「按最近到店排序」的说明或直接删掉该角标）。
2. 每行重复「最近到店」四个字 → 列表行第三行只留日期，或用一个小图标 + 日期；不要在 8 行里重复同一前缀。
3. 评分只有一个裸数字，没有单位/口径 → 右侧评分列必须有明确语义：加一个小号 `分` 或列头标注「我的评分」，或改为 `4.5` 这种一位小数 + 小号 `/5`。不要让它看起来像「次数」或「序号」。
4. 「01 / 餐厅列表」这类画板编号属于画板说明，**不应出现在手机屏幕内部**——要么删掉，要么改成真实的产品文案（如「我的餐厅」上方的计数）。请检查每屏是否都有这种「设计稿标注漏进 UI」的情况，全部清理。

### B. 评分数字权重
5. 三份原型里的评分数字都过大（24–30px），视觉权重大于店名，抢走第一焦点。
   → 列表页评分降到 **17–20px**，垂直居中对齐整行三行信息，右边缘与搜索框右边缘、列表分隔线右端**严格同一条竖线**。详情页的评分可以大（32–36px），列表页不行。
6. 评分列的右边缘、搜索框右边缘、右上「+」按钮右边缘必须是同一个 `--edge` 基准。逐个文件检查 `padding`/`margin` 是否有让某一项多出 4–8px 的偏差。

### C. 列表行节奏
7. 行内三行文字偏紧（第二、三行粘在一起），行与行之间又偏松，形成「内紧外松」。
   → 行高统一，行内第二、三行之间行距收紧但要留 2–3px 呼吸；条目之间用 1px 分隔线（D1/D3 已有则检查是否过于密集/过于空）。
8. 第二行「川菜 · 愚园路 · 8 道菜」与第三行日期在字号、颜色上过于接近，层级不成立。
   → 第二行 12–12.5px / secondary，第三行 11–11.5px / tertiary，两级必须能一眼分开。
9. 长店名不能挤压评分列：给评分列固定宽度（如 40–44px）+ 店名允许省略号截断。

### D. 底部 tab bar
10. 02 Quiet Grid 的 tab 选中态只有颜色 + 白色小横线，选中指示不足 → 必须有明确的选中反馈（实心图标 + 强调色 + 顶部 2px 指示条三选二，不要靠单个绿色短线）。
11. 三份原型的 tab 图标视觉高度/线重不一致 → 统一为 24px 视觉网格、stroke 1.75。
12. tab 标签与 home indicator 之间下边距偏紧 → 至少 12px 呼吸。
13. **导航层级要一致**：明确哪些是 tab 根页（餐厅列表 = 根），哪些是二级页。二级页（详情、菜品库、修改记录、表单）**不要带 tab bar**，改成返回 + 标题。当前 d1 的「修改记录」屏带 tab bar 与其它二级页不一致，请统一。若你认为修改记录应该是独立 tab，那三份文件都要让它一致，并在 DIRECTIONS.md 里说明。

### E. 详情页 / 修改记录 / 表单
14. 详情页顶部「编辑」和底部「编辑餐厅」大按钮重复主操作 → 只保留一个（建议保留底部主按钮，顶部改为「更多」或无）。
15. 详情页评价段落字小行距一般 → 正文 15px / 行高 1.85–1.95，段落之间 10px。
16. 修改记录屏：时间线里已经写了「评分 4→5」，下方「最近一次评分调整 4 → 5」重复 → 二选一。保留「最近一次」预览卡（它带 diff 入口），时间线那行改为只写「修改了 2 个字段」。
17. 表单页：评分「未评分 1 2 3 4 5」六个按钮在 393 宽里偏挤、触控小 → 改成「未评分」独占一行或做成 44px 高的 5 段 segmented control，触控高度 ≥44px。
18. 日期格式统一：全局只用 `2026-10-28` 或 `2026 年 10 月 28 日` 其中一种；数字与单位之间空格统一（「8 道菜」「5 分」「3 次到店」都带空格）。

### F. 对比度
19. 三个方向的辅助文字（tertiary）对比度要过 4.5:1，浅色下不要再出现接近 `#999` 的淡灰小字。若当前 tertiary 对比不足，调深并同步更新 DIRECTIONS.md 里的对比度表。

## 二、DIRECTIONS.md（必须新建）

路径：`/root/dining_log/design/proto/DIRECTIONS.md`，中文写。内容：

1. 每个方向一节：气质一句话、借的具体真实设计系统（Anthropic / Linear / Notion / 居酒屋菜单 等）+ **借用的具体规则**（不是「参考了 XX」这种空话）
2. 完整 token 表，light 与 dark 各自一格：bg / surface / ink / secondary / tertiary / border / accent / on-accent / danger、字体族、字号阶梯（列出每档 px/行高/字重）、间距、圆角、阴影、动效
3. **用 Python 实测的对比度表**：每个方向每个主题下，ink/bg、secondary/bg、tertiary/bg、on-accent/accent 的实际数值（保留两位小数），并标注是否过 AA(4.5) / AAA(7)
4. 三方向对比表：长文阅读 / 大量条目扫读 / 最不像模板 / 深色表现 / 实现成本（Compose 落地难度）
5. **明确写出你推荐哪一个**，理由要具体到版面决策（例如「列表用发丝线而非卡片，8 条数据在 393 宽下不需要横向扫描」），不要写「更现代」「更有质感」这种空话
